# Architecture decision records

Architecture decision records (ADRs) capture durable choices that cross a
system boundary, alter a review invariant, change a permission or trust
boundary, introduce difficult-to-reverse behaviour, or deliberately accept
material risk.

Routine implementation details do not require an ADR. Copy `template.md`, use
the next four-digit sequence, and name the file
`NNNN-short-decision-name.md`. Valid statuses are `Proposed`, `Accepted`,
`Superseded`, and `Rejected`.

An ADR complements the canonical product and technical specifications; it does
not silently replace them. Update the applicable source document in the same
change when a settled decision changes. Superseding decisions link in both
directions.
